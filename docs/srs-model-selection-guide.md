# SRSモデル選定ガイド — 言語学習アプリ向け

英単語・英文書に特化したFlutter製スマホアプリにおけるSRSモデルの選定資料。
ベンチマーク数値は [srs-benchmark](https://github.com/open-spaced-repetition/srs-benchmark) の「Without same-day reviews」テーブル（10,000ユーザー、約727M件のAnkiレビュー）に基づく。

---

## 1. モデル分類表

### スマホで動作可能（Flutter/Dartで実装可能）

| モデル | パラメータ数 | Log Loss↓ | 実装難易度 | 推論の仕組み |
|--------|------------|----------|-----------|-------------|
| **FSRS-rs** | 21 | 0.3443 | 低 | 数式のみ（exp, pow等）。FSRS-6のRust実装 |
| **FSRS-6 recency** | 21 | 0.3444 | 低 | FSRS-6と同じ数式、学習時の重み付けが違うだけ |
| **FSRS-6** | 21 | 0.3460 | 低 | 数式のみ。**現在使用中（デフォルトパラメータ）** |
| **FSRS-6 binary** | 17 | 0.3509 | 低 | FSRS-6のHard/Easyを統合（ボタン2つ版） |
| **GRU-P** | 297 | 0.3521 | 中 | 小型RNN（隠れ層8次元）。行列演算が必要 |
| **FSRS-5** | 19 | 0.3560 | 低 | FSRS-6の前バージョン |

**補足**: FSRS-rsとFSRS-6は同じアルゴリズム・同じ数式。学習（optimizer）の実装言語が異なるだけ（Rust vs Python/PyTorch）で、推論はどちらも同一。スコア差はoptimizerの数値精度・収束差に由来。

### サーバー推奨（参考 — 今回は採用しない）

| モデル | パラメータ数 | Log Loss↓ | 必要リソース | 推論の仕組み |
|--------|------------|----------|-------------|-------------|
| **LSTM** | 8,869 | 0.3332 | CPU可 | RNN + LayerNorm + 3出力ヘッド。Reptileメタ学習 |
| **RWKV-P** | 2,762,884 | **0.2773** | **GPU必須（CUDA）** | RNN-Transformer混合。全ユーザー一括学習 |

---

## 2. 決定事項

**FSRS-6の改良路線を採用。GRU/LSTM/RWKVは使用しない。**

理由：
- FSRS-6は数式のみでスマホ完結、オフライン動作可能
- パラメータ21個（将来の拡張後も126個程度）で軽量
- GRU-P(0.3521)よりFSRS-6(0.3460)の方が精度が高い
- サーバー側モデル（LSTM/RWKV）は運用コストに対して改善幅が限定的

---

## 3. マイルストーン（全体目安: 6ヶ月）

### Milestone 1: FSRS-6 × maimemoベースライン（Month 1-2）

**目的**: maimemoデータでFSRS-6を学習し、デフォルトパラメータとの精度差を定量化

#### やること

1. maimemoのレビューデータを前処理（srs-benchmarkと同じ形式に変換）
2. `fsrs-optimizer` でmaimemo全体の最適パラメータを学習
3. 以下4条件で比較：

| 条件 | 説明 | 期待されるLog Loss |
|------|------|-------------------|
| FSRS-6 デフォルト | 公式デフォルトパラメータ | 最も悪い（ベースライン） |
| FSRS-6 maimemo全体学習 | maimemo全ユーザーで最適化した共通パラメータ | 改善 |
| FSRS-M デフォルト | ↑と同じ（アプリ配布時のデフォルト値になる） | 同上 |
| FSRS-M ユーザー個別最適化 | ユーザーごとにパラメータを最適化 | 最良 |

※ FSRS-M = maimemoデータで最適化したFSRS-6。アルゴリズムは同一、パラメータが異なる。

#### 成果物
- maimemo最適パラメータ（21個のfloat）→ アプリのデフォルト値として組み込み
- 4条件の精度比較レポート
- ユーザー個別最適化のサーバー側パイプライン設計

#### 判断ポイント
- デフォルト vs maimemo学習の差 → **パラメータ最適化の価値**を定量化
- maimemo全体 vs ユーザー個別の差 → **個別最適化サーバーの投資判断**材料

---

### Milestone 2: CEFR難易度によるS0/D初期化（Month 3-4）

**目的**: 単語の難易度情報を活用し、初期段階の予測精度を改善

#### 背景

現状のFSRS-6は全単語が同じ初期安定度(S0)・初期難易度(D)から始まる。
A1の"apple"とC1の"ubiquitous"が同じ初期値なのは不合理。

CEFRは単語頻度をベースに教育的観点も加味したレベル分け（A1-C2の6段階）。
頻度情報と高い相関があるため、CEFRだけで十分（頻度を別途追加する必要なし）。

#### やること

1. maimemo単語→CEFRレベルのマッピングテーブルを作成
2. FSRS-6のS0初期化をCEFRレベル別に分岐

   ```
   現状:  S0 = w[rating-1]              → 4通り（評価別）
   改良:  S0 = w[rating-1] * f(CEFR)    → 最大24通り（評価×CEFR別）
   ```

3. 同様にD（難易度）の初期値もCEFR別に調整
4. Milestone 1と同じ4条件 + CEFR有無の2条件で比較（計8条件）

#### 成果物
- CEFR導入による精度改善の定量評価
- CEFRレベル別の最適S0/Dテーブル
- 追加パラメータ数と精度のトレードオフ分析

#### 判断ポイント
- CEFR導入の精度改善幅 → Milestone 3に進むかどうかの判断材料
- CEFRレベル間でS0/Dの値がどの程度異なるか → 忘却特性がレベルで違うかの検証

---

### Milestone 3: パラメータのベクトル化（Month 5-6）

**目的**: FSRS-6の全パラメータをCEFRレベル別に持ち、忘却曲線の形自体をレベル別に最適化

#### 背景

Milestone 2でS0/Dだけをレベル別にしたが、「復習後の安定度の伸び方」もレベルで異なる可能性がある。
簡単な単語は1回の復習で長期記憶に定着しやすいが、難しい単語は復習しても伸びにくいかもしれない。

#### やること

1. 21パラメータ × 6 CEFRレベル = 126パラメータのFSRS-Mを構築
2. オーバーフィット対策：
   - 全レベル共通パラメータ（21個）をベースに、レベル別の**差分だけ**を学習
   - データが少ないレベル（C1/C2等）は共通パラメータにフォールバック
3. 精度比較：

   | モデル | パラメータ数 | 説明 |
   |--------|------------|------|
   | FSRS-6 デフォルト | 21 | ベースライン |
   | FSRS-M (MS1) | 21 | maimemo全体学習 |
   | FSRS-M + CEFR S0/D (MS2) | 21 + 数個 | S0/D初期化のみCEFR別 |
   | FSRS-M ベクトル化 (MS3) | 126 | 全パラメータCEFR別 |

#### 成果物
- 全マイルストーンを通した精度改善の推移レポート
- FSRS-Mの最終仕様（パラメータ数、CEFRマッピング、フォールバック戦略）
- アプリ組み込み用の最終パラメータセット

#### 判断ポイント
- MS2 → MS3の改善幅が小さい場合、ベクトル化は不採用（S0/D初期化で十分）
- 126パラメータでもスマホ側は数式のみ・オフライン動作に影響なし

## 4. 運用アーキテクチャ

```
スマホ（Flutter/Dart）
  └─ FSRS-Mでローカル推論（オフライン対応）
     ├─ デフォルト: maimemo全体学習パラメータ（新規ユーザー用）
     └─ 個別最適化: サーバーから受け取ったユーザー固有パラメータ

サーバー（Firebase Cloud Functions / CPU）
  └─ fsrs-optimizer でユーザー個別パラメータ最適化
     ├─ トリガー: レビュー数百件ごと
     └─ 返却: 21個（or 126個）のfloat → Firestore経由でスマホに同期
```

## 5. 参考: ベンチマーク実行コマンド

**環境**: i7-9700 (8コア), RAM 16GB, RTX 2060 (VRAM 6GB)

```bash
# FSRS-6ベンチマーク（同日レビュー込み）
uv run script.py --algo FSRS-6 --short

# FSRS-6デフォルトパラメータ
uv run script.py --algo FSRS-6 --short --default

# FSRS-6 recency weighting
uv run script.py --algo FSRS-6 --short --recency
```
